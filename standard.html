MarkBottom 0.1 版本标准

MarkBottom（以下简称“mb”） 是 MarkDown（以下简称“md”） 的扩充版本，文件后缀是.mbmd（MarkBottom of MarkDown），旨在补充原版 MarkDown 中缺少的功能，此文档不是正式的标准，后续可能会存在一些删改。

mb 将支持所有 md 语法（包括标题、粗体、斜体、引用块、有序列表、无序列表、代码、分隔线、链接、图片(索引+bese64)、表格、代码块、脚注、定义列表、删除线、checkbox、下划线、双空格换行）

0. 阅读约定

  1. 本文档中所有的 markbottom 代码块都是“输入”，紧跟在它后面的 html 代码块是它“应当生成的 HTML”。表格里的 mbmd / html 两列含义相同。
  2. 除少数必须依赖脚本的功能（按钮、输入框、选择框、功能语句、媒体类型判断、公式渲染等）外，其余语法都只依赖 HTML + CSS 即可正确渲染。（这些功能在没有脚本时也要有可读的退路：媒体按图片输出、公式按原文显示。）
  3. 交互功能的 mb 源码被原样写进 data-mb 属性，由运行时读取执行（参考实现见附录 A）。这只是一种实现约定，不属于标准的一部分。
  4. 只要不产生歧义，定界符都允许使用对应的全角写法：|↔｜、/↔／`↔＼。ruby 的 【】 可写作半角 [()]。
  5. 所有成对定界符都支持嵌套，按“就近配对”匹配，内层先解析。
  6. 表格单元格里的 | 不需要转义成 \|：解析表格时先切出行内代码段（被反引号包围的部分）和排版调整语句（{|…|}），再按 | 切分单元格。

3. 详细介绍

3.1 命名语句与整体结构

一个 mb 文档的开头通常写成：

{{v:0.1}{l:"zh_CN"}}

它声明了文档使用的 mb 版本与语言。这类语句不产生可见输出，实现可以把它记录进文档元数据。

<!-- v=0.1, l=zh_CN：仅元数据，无可见输出 -->

命名语句 {#id.class1.class2} 写在要取名的元素后面，给紧挨着它前面的那个元素（或它所在的那一行 / 那一块）取名字、加类：

# 标题1 {#t1}
这一整段文字 {#note1.warn}
<h1 id="t1">标题1</h1>
<p id="note1" class="warn">这一整段文字</p>
  • # 后面是 id，只能有一个；
  • . 后面是 class，可以写多个；
  • 命名语句本身不产生输出，只修改目标元素的属性。

目标是谁：

写法目标结果
# 标题1 {#t1}它所在的那个块（标题）<h1 id="t1">标题1</h1>
这一整段文字 {#p1}它所在的那个块（段落）<p id="p1">这一整段文字</p>
**注意**{#w1}紧挨在它前面的那个行内元素<strong id="w1">注意</strong>
**注意**{.warn}只设类名<strong class="warn">注意</strong>
![猫](cat.png){#cat}紧挨在它前面的那个行内元素<img id="cat" src="cat.png" alt="猫">
# 标题1 {#t1.a.b}一次写多个类名<h1 id="t1" class="a b">标题1</h1>
|单元格{#c1}|它所在的那个单元格<td id="c1">单元格</td>
  • 前面是普通文字（文字本身不是元素）时，给它所在的那个块取名；前面是一个完整的元素时，给那个元素取名。
  • 与排版调整语句的行尾写法一致（见 3.9.4）：{|…|} 放在块 / 单元格末尾时，加的也是所在块 / 单元格的类。

规则

  1. 命名语句写在元素的后面（元素 {#id}），写法与 {|…|} 的行尾用法一致。
  2. # 后是 id（只能有一个），. 后是 class（可以写多个）：可以只设类名（{.classname}），也可以一次写多个类名（{#id.c1.c2.c3} → id="id" class="c1 c2 c3"）。
  3. 单独成行时，作用到它上面的那个块；上面还没有块时，作用到下面的那个块。

3.2 ruby text

用于显示汉语拼音、注音符号或振假名的文本形式，通常标注在汉字的上方

在 mb 中，参考了游戏引擎ren'py中的写法：

【基字|上标ruby】
这里的“|”（半角）写作“｜”（全角）也是可以的

但不同于 ren'py 的是，mb 中的 ruby 文本还支持下标：

【基字/下标ruby】
【基字|上标ruby/下标ruby】
这里的“|”“/”（半角）写作“｜““／”（全角）也是可以的

为了方便输入也可以使用[()]（只能是半角）来替代【】 同时mb应该要自动添加<rp>标签来保证不支持ruby的设备显示出来不影响阅读

当没有输入 ruby text 时 默认将给予每个字符标上“●”，可作为着重符合——但分隔符本身不能省：只有写了 |（或 /）而后面留空时，才算着重号；写成 【内容】（完全没有 | / /）不是 ruby，按普通文本原样输出（【 】 照原样显示，里面的内容照常解析）。

在日本，横排时着重点【一般标在上方|】。而中国则【一般标在下方/】

并且ruby可以嵌套：

【【基字/下标ruby】|【上标ruby|上标ruby】】

三种基本形式

写法含义ruby 位置
【基字|上标】只有上标over（默认）
【基字/下标】只有下标under
【基字|上标/下标】上下都有外层 under

上标：

【振仮名|ふりがな】
<ruby>振仮名<rp>(</rp><rt>ふりがな</rt><rp>)</rp></ruby>

下标（给 <ruby> 加 mb-ruby-under）：

【振仮名/ふりがな】
<ruby class="mb-ruby-under">振仮名<rp>(</rp><rt>ふりがな</rt><rp>)</rp></ruby>

上下同时标注时必须使用嵌套的 <ruby>——按 HTML 规范，多个 <rt> 会并排而不是叠放，只有把内层 ruby 当作外层 ruby 的 base text 才能上下各放一条注释：

【紅玉|モミだま/ルビ】
<ruby class="mb-ruby-under"><ruby class="mb-ruby-over">紅玉<rp>(</rp><rt>モミだま</rt><rp>)</rp></ruby><rp>(</rp><rt>ルビ</rt><rp>)</rp></ruby>

注意：ruby-position 是继承属性，而且只作用于「ruby 注释容器」（<ruby> / <rtc>）——直接写在内层 <rt> 上是不生效的。正确做法是：把 mb-ruby-under 加在外层 <ruby> 上，同时给内层 <ruby> 显式加 mb-ruby-over 把它压回上方。这样才能做到「上标在上、下标在下」。

<-[Bigger Text]-> 与 ->[Smaller Text]<-
<span class="mb-bigger">Bigger Text</span> 与 <span class="mb-smaller">Smaller Text</span>

其他写法：

+[Bigger Text]+ 与 -[Smaller Text]-
<span class="mb-bigger">Bigger Text</span> 与 <span class="mb-smaller">Smaller Text</span>

规则：<-[...]->／+[...]+ 一律解析为变大；->[...]<-／-[...]- 一律解析为变小。因为变小用的 -[...]- 与删除线 ~~ 不冲突，可以共存。内容中若要出现 ]-、]+ 等序列，需要用转义符。

3.4 上标 / 下标

x^[2]^ + y_[1]_
x<sup>2</sup> + y<sub>1</sub>

规则

  1. 定界符必须成对出现；^ 中的内容再出现 ^ 时按就近配对处理。
  2. 上标/下标不能互相嵌套（^[a_[b]_]^ 中的 _[]_ 不生效，算作普通文字）。
  3. 因为下划线已经被 _[…]_（下标）和 _(…)_（注解）占用，mb 把单个下划线包裹的 _文字_ 定义为下划线——编译成 <u>文字</u>；斜体一律用 *文字*。这是 mb 与 md 的一处有意差异。

  • 灰色：降低不透明度，用于弱化说明文字。
  • 注解：渲染成小一号、淡色、并自动用 ::before/::after 补上左右括号的夹注。
  • 涂黑的隐藏文本：前景色与背景色相同，鼠标悬停（:hover）后才显示，用于“剧透/敏感内容”。

规则：三者都是一行内元素，可互相嵌套（如 @(_(x)_)@）；@( )@ 内容里的 ) 需要用 \) 转义。

3.7 折叠块

使用 ~[折叠块标题][内容] 创建折叠块，默认将只展示标题，并在前面加上一个三角形，点击后展开文本。

还可以使用 ~[折叠块标题]:[内容] 创建默认展开的折叠块。

使用 ~[折叠块标题][内容][收起文本] 创建的折叠块在展开后，标题会消失，取而代之的是末尾的收起文本（省略后将默认显示为“▲”），同样支持通过在标题和内容间添加“:”默认展开

三种形式开头的 ~ 是定界符的一部分，不能省略——[标题][内容] 不会被（也不该被）当成折叠块。

基础形式

~[折叠块标题][这是一堆文本。]
<details class="mb-fold">
  <summary>折叠块标题</summary>
  这是一堆文本。
</details>

默认展开：

~[折叠块标题]:[这是一堆文本。]
<details class="mb-fold" open>
  <summary>折叠块标题</summary>
  这是一堆文本。
</details>

末尾收起文本形式

~[展开][一堆文本][收起]
<span class="mb-fold-inline">
  <input type="checkbox" id="mb-fold-7" class="mb-fold-state">
  <label for="mb-fold-7" class="mb-fold-title">展开</label>
  <span class="mb-fold-body">一堆文本</span>
  <label for="mb-fold-7" class="mb-fold-close">收起</label>
</span>

规则

  1. 三种形式由“第三段是否存在”区分：只有两段时用 <details>；有三段时用“checkbox + label”的纯 CSS 折叠（这样展开时标题才能消失、末尾才出现收起文本）。
  2. 三段式中第三段为空（~[标题][内容][]）时，收起文本默认显示为 ▲。
  3. 三段式默认展开时写成 ~[标题]:[内容][收起]，对应 <input … checked>。
  4. id 必须全局唯一，实现需要自行生成（如上例的 mb-fold-7）；同一页有多个折叠块时必须各不相同。
  5. 收起文本原样显示，前后不加任何装饰符；标准只要求给“标题”前面加一个三角形。
  6. 一般折叠块是块级的：可以放在段落之间，也可以放在表格单元格里（放在单元格里时它就是个普通的块级折叠块，只折自己那一格里的内容）；但不要放在列表项中间——它会打断列表。要折叠表格行、列表项，请用下面的分离式折叠块。

分离式折叠块

一般折叠块把“按钮”和“内容”写在了一起；分离式折叠块把它们拆成两处，专门用来折叠列表项和表格行：

  • ~[标题]~>[标识符]：生成折叠按钮（行内元素），放在你想让按钮出现的地方——段落里、表格单元格里、列表项里都行；
  • [标识符]~>[内容]：表示被折叠的内容。~> 后面的 [ … ] 就是内容的边界，可以跨多行。

开头的 ~ 和两处方括号都是必需的，一个都不能省。

折叠表格行：

  2. 内容的 [ … ] 按方括号配对找收尾（内容里可以出现 […]）；收尾的 ] 单独占一行最好读。
  3. 内容里的每一行都原样参与解析——以 | 开头就是表格行，以 - / 1. 开头就是列表项，其余按普通文本处理。（[标识符]~>[ 后面剩下的文字、以及收尾 ] 前面剩下的文字都不算一整行；内容里真正的空行会结束“并入表格 / 列表”这件事。）

  6. 不在表格 / 列表里时，整段内容作为一个块被隐藏或显示。
  7. 折叠按钮本身只是行内的 <input type="checkbox"> + <label>，所以能放在任何行内位置。
  8. 内容行里不能再嵌一个分离式折叠块。

3.8 按钮式连接

让一个链接看起来像按钮：

[[示例链接](example.com)]
<a class="mb-btn" href="example.com">示例链接</a>

规则

  1. [[ … ]] 里第一个完整的一对方括号是“显示文本”，紧跟在后面的 ( … ) 是链接地址。
  2. 显示文本为空时，用地址本身作为显示文本。
  3. 与“按钮”的区别：按钮式连接是静态链接（<a href>），按钮是交互控件（<button> + data-mb）。当 [[ ]] 里出现了执行语句时，一律按“按钮”处理。

3.9.2 内容语句

内容语句用来生成一些难以输入的字符，格式为{:分类:名称或参数:}。

标准的分类包括：

  • greek
  • unicode
  • control
  • emoji
  • icon
{:greek:alpha:} {:greek:Alpha:} {:greek:pi:}
{:unicode:1F600:} {:unicode:00E9:}
{:control:nbsp:} {:control:copy:} {:control:hellip:}
{:emoji:smile:} {:emoji:heart:}
{:icon:warning:} {:icon:check:}
α Α π
😀 é
&nbsp; &copy; &hellip;
😄 ❤️
⚠️ ✅

规则

  1. 语法是 {: + 分类 + : + 名称或参数 + :}；三个冒号都不可省略。
  2. greek 的名称首字母大写表示大写希腊字母（alpha→α，Alpha→Α）。
  3. unicode 的参数是十六进制码位，大小写均可，不带 U+。
  4. control 的名称是 HTML 实体名（不含 & 和 ;），输出实体本身。
  5. emoji / icon 可以加肤色、样式等后缀参数：{:emoji:thumbsup:dark:}；它们直接输出字符本身，不额外包标签（想读屏友好的实现可以自行加 role="img" 与 aria-label，但那不属于标准）。
  6. 未知名称应当原样输出该语句，而不是丢弃。

3.9.3 执行语句

执行语句用来执行一些操作，格式为{{函数名:参数}{函数名:参数}{函数名}...}，当它们被单独放置在一行的时候就会自动执行。当加在按钮/输入框等元素（我称之为“触发器”）内时则是条件触发

标准的函数包括：

  • v，用于声明 mb 版本
  • l，用于声明文档语言
  • put，用于在该语句之后插入文本
  • rplcStart，无参数，用于标记rplc函数的替换开始位置
  • rplcEnd，无参数，用于标记rplc函数的替换结束位置
  • rplc，向上匹配最近的 rplcStart 标记，向下匹配最近的 rplcEnd 标记，并删除它们之间的内容（包括标记本身），替换为新的内容
  • t，设置页面标题，如 {{t:"标题"}}
  • trigger，trigger:"flag"：把同一组里它后面的那些功能语句记在 flag 名下，先不执行
  • call，call:"flag"：在原来 trigger 的位置执行 flag 名下那串语句（如 put 的结果就出现在原处）
  • use，use:"flag"：在 use 语句所在的位置执行 flag 名下那串语句
  • quote，quote:"地址[范围]"：引用其他 mbmd 文件的内容，插在该语句的位置（见 3.24）

单独成行时：

{{put:"hello world"}}
<span class="mb-exec" data-mb="{{put:&quot;hello world&quot;}}"></span>

运行时执行后，文档中这一处会出现 hello world。

作为触发器的一部分时：

[[点我]{{put:"111"}}]
<button type="button" class="mb-btn" data-mb="{{put:&quot;111&quot;}}">点我</button>

计算与替换：

1+1={`1+1`}
{{rplcStart}}这里的内容会被整段删掉{{rplcEnd}}{{rplc:"新的内容"}}
1+1=<span class="mb-exec" data-mb="{{put:1+1}}"></span>
<span class="mb-exec" data-mb="{{rplcStart}}"></span>这里的内容会被整段删掉<span class="mb-exec" data-mb="{{rplcEnd}}"></span><span class="mb-exec" data-mb="{{rplc:&quot;新的内容&quot;}}"></span>

执行之后，页面上分别显示 1+1=2 和 新的内容（被标记包住的那一段连同两个标记一起消失）。

规则

  1. 外层 { } 里可以放一个或多个 {函数名:参数} 单元，从左到右依次执行。
  2. 参数缺省时（{函数名}）等价于空参数。
  3. 参数中的字符串用 " 包裹，内部 " 写作 \"；参数本身可以是完整的计算语句表达式。
  4. 单独成行 → 编译为 <span class="mb-exec" data-mb="{{…}}"></span>，页面加载后立刻执行一次。
  5. 出现在触发器内部 → 编译成触发器的 data-mb 属性，只在触发时执行。
  6. put 把结果作为文本节点插到该语句之后，重复触发时重复插入；插入的文本会被当成 mb 文本再解析一遍，并且会与紧邻的已有文本合成新的 mb 文本（例：页面上已有 a*，put 在它前面输出 *a，就合成斜体 *aa*）（这也是它的正常语义）。
  7. rplc 只作用于同一文档中最靠近的一对标记；标记未成对出现时 rplc 不执行任何操作，并在控制台给出警告。rplc 语句写在两个标记之间也可以——被删掉的是一对标记连同它们之间的全部内容（rplc 语句自己也一起消失），替换出来的文本同样按 mb 文本再解析。
  8. {{a}}{{b}} 与 {{a}{b}} 等价，实现两者都要能正确拆分（转换器会把前者规范成后者）。属性值中的 " 必须写成 &quot;，& 写成 &amp;，< 写成 &lt;。

3.9.4 排版调整语句

主要有{|:---:|} {|:---|} {|---:|}，分别对应居中、左对齐、右对齐。被放置在单独的行时会改变该语句下方的文本对齐模式，也可以放在一行后面或者某个表格的一个单元格的结尾对它们进行单独调整对齐。

它还有改变元素嵌入位置的功能：{|===|}可以让元素单独占一行，{|--.5|}可以让元素贴在下一段文本右侧并占据5行高度，{|-.1-|}可以让元素插入所在文本的中间并占据1行高度，{|.6--|}可以让元素贴在下一段文本左侧并占据6行高度。该语句主要用于对插图的位置进行调整，但也可作用于其他元素。该排版调整功能可以和上一个合用如{|===:|}能让文本右对齐并单独占一行

① 对齐

写法含义加上去的类

{|:---|}左对齐mb-left
{|---:|}右对齐mb-right

单独成行时，它把下方的块级内容包进一个带类的容器：

{|:---:|}
这是居中的段落。

<p>这是居中的段落。</p>
</div>

放在行尾时，它修改本行所属的块：

这一行右对齐{|:---:|}
<p class="mb-right">这一行右对齐</p>

放在表格单元格末尾时，它修改该单元格：

| 内容{|:---:|} | 普通内容 |
<table><tbody><tr><td class="mb-right">内容</td><td>普通内容</td></tr></tbody></table>

② 元素嵌入位置

写法含义加上去的类
{|===|}元素单独占一行（md 里图片的默认策略就是这个）mb-block
{|--.5|}元素贴在下一段文本右侧，占 5 行高mb-float-right
{|.6--|}元素贴在下一段文本左侧，占 6 行高mb-float-left
{|-.1-|}元素插入文本中间，占 1 行高mb-inline-middle

格式可以记成 {| <左侧标记> . <行数> <右侧标记> |}：. 前面有 - 表示左侧有文字环绕，. 后面有 - 表示右侧有文字环绕，两侧都有则元素插在中间；=== 表示独占一行。

{|--.5|}
![一只猫](cat.png)
<div class="mb-float-right" style="height: 5em"><img src="cat.png" alt="一只猫"></div>

③ 合用

对齐标记 : 与位置标记可以写在一起，位置在前、对齐在后（用 : 结尾表示右对齐、开头表示左对齐、两端都有表示居中）：

{|===:|}
![一只猫](cat.png)
<div class="mb-block mb-right"><img src="cat.png" alt="一只猫"></div>

规则

  1. 排版调整语句本身不产生可见输出，它只是给目标元素追加类名。
  2. === 与 -…- 互斥；同时出现时以 === 为准。
  3. “行数”是浮点数，编译成 style="height: <n>em"（约等于行高的倍数）。
  4. === 表示元素独占一行——这本来就是 md 里图片的默认显示策略，所以对图片来说 {|===|} 相当于显式声明，主要用途是把行内的元素恢复成块级。
  5. 浮动 / 占位容器有明确高度时（{|--.5|} → height: 5em），里面的元素应当按容器高度缩放（图片用 max-height: 100%）——否则图片比容器高就会溢出到容器外面、压住下面的正文（浏览器不会为溢出的部分让路）；容器里若只有一个元素（例如一张图），编译时不要再套一层 <p>（与上面的示例一致），这样元素直接以容器为参照。容器本身也带同一个高度上限（{|--.40|} 这种很大的行数不会真的超过 75vh，见 3.21 规则 11）。
  6. 排版调整语句写在元素所在那一行的末尾（![图](…) {|--.5|}）与单独成行（写在元素上方）完全等价，都要编译成同一个容器——只把类加到那一段的 <p> 上是不行的：那样容器没有 height，里面的元素缩不下去。
  7. 「行数」只对元素（图片这类有固定尺寸的东西）有意义：普通文字段落的高度由文字自己决定，给它套 height 反而会让文字溢出容器。

3.9.5 解析语句

加在代码块或原始文本块前面，略过一些结束标识的解析。

{/`=3}`test` ` `text
<code>test` ` `text</code>

规则

  1. 形式为 {/`=n}，n 是非负整数，表示接下来的那个块在遇到结束标识时，前 n 次不结束。
  2. 因此可以写出“内容里包含结束标识”的代码/原始文本块，而不必转义。
  3. 它本身不产生任何输出，只影响解析；如果 n 比块里实际出现的结束标识还多，则块一直延伸到行尾/块尾。

与计算语句（3.9.7）不冲突：计算语句用「{ + 反引号」开始、「反引号 + }」结束，而本节的解析语句用 {/ 开始、} 结束。

3.9.7 计算语句

用于计算表达式并直接显示结果，但如果在触发器后面则不会显示结果，这些运算方法也可以传入执行语句的参数中

定界符：开始符是「{ 紧接一个反引号」，结束符是「一个反引号紧接 }」，也就是 { + 反引号 + 表达式 + 反引号 + }。因此它和以 {/ 开头、以 } 结尾的解析语句（3.9.5）完全不会冲突。

1 + 1 = {`1+1`}
1 + 1 = 2

[[算一下]{{put:1+1}}]
<button type="button" class="mb-btn" data-mb="{{put:1+1}}">算一下</button>

[[算一下]{{put:2*3+4}}]

3.10 按钮

[[点击计算"1+1"]{{put:1+1}}]
<button type="button" class="mb-btn" data-mb="{{put:1+1}}">点击计算"1+1"</button>

最简按钮：

[[点我]{{put:"hello"}}]
<button type="button" class="mb-btn" data-mb="{{put:&quot;hello&quot;}}">点我</button>

用 {#id} 给按钮命名，以便作为输入框的回车键按钮：

[[点我]{{put:"hello"}}]{#btnid}
<button type="button" class="mb-btn" id="btnid" data-mb="{{put:&quot;hello&quot;}}">点我</button>

规则

  1. [[ ]] 的第一段是按钮文字，其余部分（执行语句）编译进 data-mb。
  2. 按钮文字里可以写 {:unicode:…:}、^{} 等行内语法；也可以写 $变量$，在点击时求值（文字部分不存在时用 $cntnt$ 得到空串）。
  3. 按钮默认是 <button type="button">，避免在 <form> 里误触发提交。
  4. 每一次点击都执行一次；执行顺序从左到右。

3.11 输入框

:[placeholder](default content)->(#btnid){{put:"primer"+:$cntnt$}}
<input type="text" class="mb-input" placeholder="placeholder" value="default content"
       data-mb-enter="#btnid" data-mb="{{put:&quot;primer&quot;+:$cntnt$}}">
<button type="button" id="btnid" class="mb-btn">确定</button>

规则

  1. : 开头，[ ] 是 placeholder，( ) 是默认内容（可省略）。
  2. ->(#id) 声明的是回车键所对应的那个按钮：在这个输入框里按下回车，等价于点击 id 为 id 的按钮（就像 HTML 表单里的默认提交按钮）。编译时写成 data-mb-enter="#id"。
  3. 输入框自己的执行语句在 change 时执行（失焦，或在框里按回车提交时），此时 $cntnt$ 等于输入框当前的值。
  4. ->(#id) 省略时，回车不会去点任何按钮。
  5. 编译时 " 必须转义为 &quot;。
  6. 也可以用 <form> 实现：把输入框和 #id 那个按钮放进同一个 <form>，并让该按钮成为表单的默认提交按钮（type="submit"），效果完全相同。

3.12 多行输入框

[:[placeholder](default content){{put:"primer"+:$cntnt$}}]
<textarea class="mb-input" placeholder="placeholder"
          data-mb="{{put:&quot;primer&quot;+:$cntnt$}}">default content</textarea>

规则

  1. 就是在输入框语法外面多套一层 [ ]。
  2. 内容里的换行原样保留。
  3. 在 change（失焦）时触发。->(#id) 对多行输入框意义不大——回车在 <textarea> 里是换行——实现可以忽略它，或把它解释成 Ctrl+Enter。
  4. 触发后编译成普通文本节点（不再可编辑），并保留原有换行（white-space: pre-wrap）。

3.13 选择框

[;[placeholder][option1][option2][option3](default){{put:"you selected"+:$cntnt$}}]
<!-- “(default)” 不是任何一个选项的文字，所以这里没有 option 带 selected -->
<select class="mb-input" data-mb="{{put:&quot;you selected&quot;+:$cntnt$}}">
  <option value="" disabled hidden>placeholder</option>
  <option value="option1">option1</option>
  <option value="option2">option2</option>
  <option value="option3">option3</option>
</select>

规则

  1. [; 开头，第一个 [ ] 是占位提示（对应一个 disabled hidden 的 <option>），之后每个 [ ] 是一个选项。
  2. ( ) 里写要默认选中的选项文字，对应 <option selected>；省略时不预选。
  3. 选中项变化时触发一次，$cntnt$ 为选中项的文本。
  4. 想要“显示文字”与“提交值”不同，写成 [显示=值]，编译成 <option value="值">显示</option>。

3.14 标签

::Label 生成一个 HTML <label>，作用就是 HTML <label> 的作用：把一段文字和一个可交互元素绑定在一起，点击这段文字就等于点击那个元素（聚焦输入框、勾选 checkbox 等）。

基础形式：

::Label
<label class="mb-label">Label</label>

自动绑定：只要在标签后面紧跟着放一个可交互元素，它就会自动绑上去：

::user name: :[input your name]()
<label class="mb-label">user name
  <input type="text" class="mb-input" placeholder="input your name">
</label>

规则

  1. 标签由 :: 开始，结束位置取下面三者中最靠前的一个：一个 :（结束用的冒号）、第一个可交互元素的起始处（见规则 3）、行尾。所以下面三种写法完全等价（结尾的 : 和空格都可以省）： 
     ::user name: :[input your name]()
 ::user name :[input your name]()
 ::user name:[input your name]()
  2. ::文字: 单独出现时编译为 <label class="mb-label">文字</label>（没有绑定对象，就是个普通标签）。
  3. 标签后面同一行内有可交互元素时，编译成包裹式： 
     <label class="mb-label">文字 <可交互元素></label>

    点击文字即可聚焦 / 勾选，效果与点击控件本身相同。

  4. 解析器向后找第一个可交互元素当作绑定对象：它必须紧跟在结束位置之后（中间只允许有空格）；标签文字就是结束位置之前的内容。整行都找不到可交互元素时退化成普通 <label>。
  5. 可绑定的元素有：输入框 :[…](…)、多行输入框 [:…]、选择框 [;…]、按钮 [[…]]、任务列表的 checkbox。
  6. 绑定对象不需要用 ->(#id) 指定——把元素放在标签后面就行（->(#id) 是 3.11 输入框里用来指定回车键按钮的语法）。
  7. 结束用的 : 和空格都不是必需的，解析器靠“向后找第一个可交互元素”来断句；但仍建议写成 ::文字: 元素（一个冒号 + 一个空格），最不容易产生歧义。
  8. 标签文字里的 : 用 \: 转义；文字不得为空。
  9. 与“按钮式连接”的区别：<a> 会跳转，<label> 只是把焦点 / 勾选交给控件，不改变页面位置。

\n\<\>
<br>&lt;&gt;
写法输出
\n换行 <br>

3.16 原始文本

[o[origin         al]o]
<span class="mb-origin">origin         al</span>

规则

  1. [o[ 与 ]o] 之间的内容不做任何解析，连续空格、制表符、换行都原样保留；可以跨行书写（在源文件里直接换行，空行也不打断——收尾靠的是 ]o] 本身）。
  2. 内容中要出现 ]o] 时，用 {/`=n} 略过 n 次。
  3. 与 md 的“行内代码 `”不同：原始文本不换字体、不做等宽处理，只保留空白；需要等宽请用代码。

3.17 原始转义符

\o 后面紧跟的一个字符不会被解析，直接原样输出。

\o!\o[这不是一个链接](example.com)
![这不是一个链接](example.com)

![…](…) 本来会被解析成一张图片，\o 分别挡住了 ! 和 [，于是整段原样输出。

单个字符的例子：

\o*星号还是星号\o*
*星号还是星号*

规则

  1. \o 与 \ 一样，只作用于紧跟其后的一个字符；区别是它固定消费两个字符（o 只是个标识），所以可以安全地转义字母：\on 输出字母 n，而 \n 是换行。
  2. 被 \o 转义掉的字符不再参与任何后续解析——mb 和 md 都不会解析它。
  3. 想输出一个 o 本身，写 \oo（\o 吃掉第二个 o，只输出 o）。
  4. 实现应当把 \oX 与 \X 一视同仁；但如果 X 是 n、t 这类具名转义的首字母，\o 形式一律按“字母本身”处理（\on → n，而 \n → 换行）。
  5. 由于它只管一个字符，要挡住一整段内容时，需要给这段里每一个“能启动语法”的字符都加 \o。
  6. 后面没有字符（行尾孤零零一个 \o）时按普通文字输出。

规则

  1. 定界符 %( / )% 的位置决定线的汇聚角：写在前面的 % 表示汇聚角在左（配合 / 即左下，配合 \ 即左上）；写在后面的 % 表示汇聚角在右（配合 / 即右上，配合 \ 即右下）。% 只能出现在一侧——两侧都写（%( … )%）是非法写法，实现应当原样输出并给出警告。
  2. / 型斜线用 mb-slash-u（左下→右上），\ 型用 mb-slash-d（左上→右下）。
  3. 单元格内的文本按书写顺序，从左往右依次填入被斜线分割出来的各个块：
    • / 型（左下→右上）分割出的块从左往右是「左上 → 右下」，所以第一段填左上、最后一段填右下；
    • \ 型（左上→右下）分割出的块从左往右是「左下 → 右上」，所以第一段填左下、最后一段填右上。

    三段以上时同样按从左往右的顺序沿汇聚角扇形排开。

  4. 斜线单元格里不能再放 [+] / [+>]。
  5. 斜线单元格必须使用绝对定位的 <span> 承载文字，因为斜线本身由 ::before 绘制。

规则

  1. 语法与 md 的图片一致：![替代文本](地址)；替代文本照旧写进 alt（音频有封面时，写进封面那个 <img> 的 alt）。
  2. 类型只看文件内容，不看后缀：photo.jpg 里装的若是 PNG 就按 PNG 处理；song.txt 里装的若是 FLAC 就按音频播放。

  4. 有封面时，封面与控件一起放进一个行内块容器 .mb-media-cover（封面在上、控件在下）。不要用 <figure>：这段语法常常出现在 <p> 里，块级元素会把段落截断。
  5. 这三种元素都是行内级的（<img>、<video>、<audio> 本身都是行内元素），可以放在段落、表格单元格与列表项里；要独占一行请用排版调整语句 {|===|}（见 3.9.4）。
  6. 编译时一律先输出基本形态 <img>，等运行时判断出是视频 / 音频再替换成对应元素。这样即使没有脚本、或取不到内容，最差也只是显示成图片，不会整段消失。（参考实现会给这个 <img> 额外加一个 data-mb-media="地址"，好让运行时知道该去探哪个地址——与 data-mb 一样，这只是实现约定，不属于标准，见第 0 节第 3 条。）
  7. 判断类型必须读取内容，所以这一步需要脚本（与按钮、输入框、功能语句一样，见第 0 节第 2 条）；没有脚本时一律按图片输出。
  8. 读取内容时应当只取需要的字节（用 Range 请求，或读够就停），不要把整个视频读进内存。
  9. 取不到内容时（跨域、离线、404、本地文件）按图片输出，并在日志里说明原因；实现可以再退一步、用 <video preload="metadata"> 的 loadedmetadata 事件探一次（能读出画面尺寸是视频、只有声音是音频），这一步不需要跨域许可。
  10. 视频 / 音频应当带上可访问名称：写成 ![替代文本](地址)((描述))（见 3.22）；没有写 ((…)) 时，用替代文本当 aria-label。
  11. 媒体的尺寸上限：宽 ≤ min(100%, 90vw)（不超过所在栏宽，同时不超过视口的 90%）、高 ≤ 75vh（不超过视口高度的 75%）。这样不论横图、竖图，都不会把整屏占满。

3.22 aria-label（无障碍标签）

有些元素需要一段给读屏软件听的文字（视频、音频、只有图标或只有图片的按钮……）。mb 的写法是：在元素的后面紧跟一对双层圆括号：

![图片](url)((一张猫的照片))
<img src="url" alt="图片" aria-label="一张猫的照片">

规则

  1. ((描述)) 写在要加标签的元素后面，编译成 aria-label="描述"；定位规则与命名语句（3.1）完全相同：
    • 前面是一个完整的元素 → 加在那个元素上；
    • 前面是普通文字（不是元素）→ 加在它所在的那个块上（标题 / 段落 / 列表项 / 表格单元格）。
  2. 单独成行时，作用到它上面的那个块；上面还没有块时，作用到下面的那个块。
  3. 描述里的 "、&、<、> 要按属性值转义（与其它属性一样）。
  4. 同一个元素上，命名语句与 ((…)) 可以一起用，先后不限：![猫](cat.png){#cat}((一只猫))。
  5. ((…)) 是可选的；但对没有可见文字的元素（3.21 的视频 / 音频、3.9.6 的图表等）应当带上可访问名称。
  6. 与 _(…)_（注解，见 3.5）不同：注解是显示出来的可见文字，((…)) 只写进属性，不显示。
  7. 正文里想原样显示 (( 时，用转义符 \(（见 3.15）。

3.23 LaTeX 公式

写法含义生成的 HTML
$公式$行内公式（不换行）<span class="mb-math" data-mb-tex="公式">公式</span>
$$$ … $$$行间公式（独占一行、居中，可以跨行）<div class="mb-math-block" data-mb-tex="公式" data-mb-display="1">公式</div>
质能方程 $E = mc^2$ 是这么来的。

$$$
\int_0^1 x^2\,dx = \frac{1}{3}
$$$
质能方程 <span class="mb-math" data-mb-tex="E = mc^2">E = mc^2</span> 是这么来的。

规则

  1. 行内公式是「一个 $」加公式再加「一个 $」；行间公式夹在两对 $$$ 之间（$$$ 也可以与公式写在同一行，写成一行 $$$公式$$$）。
  2. 与变量的区分：$…$ 里的内容恰好是一个合法变量名（字母 / 下划线开头，只含字母、数字、下划线）时按变量处理（见 3.9.8），否则按公式处理。想强制把一个看起来像变量名的东西当公式时，在内容前后各加一个空格（$ x $）——LaTeX 会忽略这些空格，渲染结果一样。
  3. 公式源码原样交给渲染器；\$ 会输出一个真正的 $（转义符优先，见 3.15）。公式里的 "、&、<、> 在写进 HTML 时按文本转义。
  4. 编译时把公式源码放进 data-mb-tex 属性，等页面加载后由实现渲染；没加载到渲染器时按原文显示（公式源码本身就是元素里的可见文字，不会变成空白）。
  5. 行间公式默认居中、独占一行；它中间的空行属于公式，不会终止它。
  6. 没写收尾的 $$$ 时按普通文字输出（附录 B 第 8 条）。
  7. 参考实现用 KaTeX（现成的实现）：只有文档里有公式时才引入它的 CSS / JS；渲染失败也不影响页面其它部分。

3.24 引用其他文件（quote）

{{quote:"地址[范围]"}} —— 把另一个 mbmd 文件的内容引到这一处：

{{quote:"snippets/intro.mbmd"}}
<!-- 那个文件的内容会原样插到这里，并且照常解析（标题、表格、列表、功能语句都算） -->

范围写在地址后面的方括号里；不写就是整个文件。行号从 1 开始，负数从文件末尾数（-1 是最后一行）；字符位从 1 开始，负数从行尾数；两端都是闭区间（含端点）：

写法含义
"intro.mbmd"整个文件
"intro.mbmd[3:5]"第 3 行到第 5 行
"intro.mbmd[2:-2]"第 2 行到倒数第 2 行
"intro.mbmd[3[2]:5[6]]"第 3 行第 2 个字符 → 第 5 行第 6 个字符
"intro.mbmd[3[3:10]]"第 3 行第 3 个字符 → 第 3 行第 10 个字符
"intro.mbmd[#id]"{#id} 写在哪一行，就取那一行
"intro.mbmd[#id[0]]"同上（偏移 0）
"intro.mbmd[#id[9]]"{#id} 所在行往后第 9 行
"intro.mbmd[#id[-2]]"{#id} 所在行往前第 2 行
"intro.mbmd[#id[1:2]]"从「所在行 + 1」到「所在行 + 2」
"intro.mbmd[#id1[0]:#id2[9]]"从 #id1 所在行到 #id2 所在行 + 9
"intro.mbmd[#id[1[2]:3[4]]]"「所在行 + 1」的第 2 个字符 →「所在行 + 3」的第 4 个字符
"intro.mbmd[#id[1[2:9]]]"「所在行 + 1」的第 2 个字符 → 第 9 个字符
"intro.mbmd[#id1[1[2]]:#id2[3[4]]]"#id1「所在行 + 1」的第 2 个字符 → #id2「所在行 + 3」的第 4 个字符

规则

  1. 地址是字符串（用 " 包起来），里面写 URL 或相对路径；范围紧跟在地址后面的 [ ] 里（方括号只写一个，范围的两端用 : 分开）。
  2. #id 指的是那个文件里写了 {#id} 的那一行（命名语句写在元素后面，所以它就是元素所在的行）；偏移量是相对这一行的行数（0 = 这一行本身，9 = 往后 9 行，-2 = 往前 2 行）。找不到这个 id 时，这一处引用留空并给出一条提示。
  3. 取多行时：第一行从起始位置到行尾，中间各行整行，最后一行从行首到结束位置；同一行内取字符时就是普通的下标切片。
  4. 引用的内容插在该语句的位置，并且照常解析——等价于把那段文字直接写在文档里。
  5. 只有单独成行、且这一行只有这一条 quote 语句时才在编译期取回来（这样它和文档其它部分完全一样）；写在按钮 / 输入框 / 触发器里，或者和别的语句写在同一组时，留给运行时执行——运行时用同一个编译器把引用来的内容整段解析成 HTML 再插进来，所以标题、引用、竖排、原始文本、表格、列表、折叠块、按钮、输入框、图表、脚注、checkbox、LaTeX 公式以及各种功能语句全都会照常解析（插进来的那一片会紧接着接上运行时，所以里面的功能语句、媒体、公式也会当场生效）。两者的区别只是时机：编译期那条路在文档加载前就完成，运行时那条路要等内容取回来才出现。
  6. 取不到内容时（跨域、离线、404、路径不对），这一处保留原语句并在日志里说明原因，不影响文档其它部分。
  7. 被引用进来的内容里若也有 quote 语句，不会在编译期再展开（避免递归）；它只会由运行时按行内方式处理。
  8. 与媒体（3.21）一样，这一步要读网络内容，所以需要能跨域读取。

/* mb.js —— MarkBottom 0.1 参考运行时 */
(function () {
  'use strict';

  /* ---------- 0. 内置变量 ---------- */
  var GLOBAL = Object.create(null);
  function pad(n) { return String(n).padStart(2, '0'); }
  function tick() {                       // 时间类变量：每次调用时重新取一次
    var d = new Date();
    GLOBAL.timeh = pad(d.getHours());
    GLOBAL.timem = pad(d.getMinutes());
    GLOBAL.times = pad(d.getSeconds());
    GLOBAL.timeY = String(d.getFullYear());
    GLOBAL.timeM = pad(d.getMonth() + 1);
    GLOBAL.timeD = pad(d.getDate());
  }
  tick();
  GLOBAL.browser = navigator.userAgent;
  GLOBAL.os = navigator.platform ||
    (navigator.userAgentData ? navigator.userAgentData.platform : '');

  /* ---------- 1. 词法分析 ---------- */
  var TOKEN_RE = new RegExp(
    '\\s*(' +
      '\\d+(?:\\.\\d+)?' +                     // 数字
      '|"(?:[^"\\\\]|\\\\.)*"' +               // 字符串
      '|\\$[A-Za-z_][A-Za-z0-9_]*\\$' +        // 变量
      '|\\+:|\\-:|%:|>:' +                     // 字符串运算
      '|\\+\\+|--|\\+=|-=|\\*=|\/=' +          // 赋值类
      '|>=|<=|==|!=' +                         // 比较
      '|\\.-|\\.\\+|\\.\\?' +                  // 取整
      '|[+\\-*/%()\\[\\],=!|&<>?:]' +          // 单字符
    ')', 'y');

  function tokenize(src) {
    var out = [], i = 0, m;
    while (i < src.length) {
      if (/\s/.test(src[i])) { i++; continue; }
      TOKEN_RE.lastIndex = i;
      m = TOKEN_RE.exec(src);
      if (!m) throw new SyntaxError('非法字符：' + src[i]);
      out.push(m[1]);
      i = TOKEN_RE.lastIndex;
    }
    return out;
  }

  function truthy(v) {
    return !(v === '' || v === 0 || v === '0' ||
             v === false || v === null || v === undefined);
  }

  /* ---------- 2. 表达式求值（递归下降） ---------- */
  function evaluate(src, scope) {
    var toks = tokenize(src), p = 0;
    var peek = function () { return toks[p]; };
    var eat = function (t) { if (toks[p] === t) { p++; return true; } return false; };
    var expect = function (t) {
      if (!eat(t)) throw new SyntaxError('期望 “' + t + '”，实际是 “' + toks[p] + '”');
    };
    var getVar = function (n) {
      if (n === 'cntnt') return scope.cntnt === undefined ? '' : scope.cntnt;
      if (n in scope) return scope[n];
      if (n in GLOBAL) return GLOBAL[n];
      return '';
    };
    var setVar = function (n, v) {
      if (n === 'cntnt') scope.cntnt = v; else scope[n] = v;
      return v;
    };

    function conditional() {
      var c = assignment();
      if (eat('?')) {
        var a = conditional();
        expect(':');
        var b = conditional();
        return truthy(c) ? a : b;
      }
      return c;
    }

    function assignment() {
      var t = peek();
      if (t && t.charAt(0) === '$') {
        var name = t.slice(1, -1), op = toks[p + 1];
        if (op === '=' || op === '+=' || op === '-=' || op === '*=' || op === '/=') {
          p += 2;
          var old = getVar(name), rhs = assignment();
          if (op === '=')  return setVar(name, rhs);
          if (op === '+=') return setVar(name, Number(old) + Number(rhs));
          if (op === '-=') return setVar(name, Number(old) - Number(rhs));
          if (op === '*=') return setVar(name, Number(old) * Number(rhs));
          return setVar(name, Number(old) / Number(rhs));
        }
        if (op === '++' || op === '--') {
          p += 2;
          var v0 = Number(getVar(name));
          setVar(name, op === '++' ? v0 + 1 : v0 - 1);
          return v0;
        }
      }
      return or();
    }

    function or() {
      var v = and();
      while (eat('|')) { var r = and(); v = truthy(v) || truthy(r); }
      return v;
    }
    function and() {
      var v = equ();
      while (eat('&')) { var r = equ(); v = truthy(v) && truthy(r); }
      return v;
    }
    function equ() {
      var v = rel();
      for (;;) {
        if (eat('==')) v = (v == rel());
        else if (eat('!=')) v = (v != rel());
        else return v;
      }
    }
    function rel() {
      var v = strOps();
      for (;;) {
        if (eat('>=')) v = (v >= strOps());
        else if (eat('<=')) v = (v <= strOps());
        else if (eat('>'))  v = (v >  strOps());
        else if (eat('<'))  v = (v <  strOps());
        else return v;
      }
    }
    function strOps() {
      var v = add();
      for (;;) {
        if (eat('+:')) { v = String(v) + String(add()); }
        else if (eat('-:')) { v = String(v).split(String(add())).join(''); }
        else if (eat('%:')) {
          var oldS = add();
          if (!eat('>:')) throw new SyntaxError('“%:” 必须与 “>:” 配对使用');
          v = String(v).split(String(oldS)).join(String(add()));
        } else return v;
      }
    }
    function add() {
      var v = mul();
      for (;;) {
        if (eat('+')) v = Number(v) + Number(mul());
        else if (eat('-')) v = Number(v) - Number(mul());
        else return v;
      }
    }
    function mul() {
      var v = unary();
      for (;;) {
        if (eat('*')) v = Number(v) * Number(unary());
        else if (eat('/')) v = Number(v) / Number(unary());
        else if (eat('%')) v = Number(v) % Number(unary());
        else return v;
      }
    }
    function unary() {
      if (eat('!')) return !truthy(unary());
      if (eat('-')) return -Number(unary());
      if (eat('+')) return Number(unary());
      return postfix();
    }
    function postfix() {
      var v = primary();
      for (;;) {
        if (eat('[')) {
          var n = conditional();
          expect(']');
          v = String(v).charAt(Number(n) - 1);   // 从 1 开始计数
        }
        else if (eat('.-')) v = Math.floor(Number(v));
        else if (eat('.+')) v = Math.ceil(Number(v));
        else if (eat('.?')) v = Math.round(Number(v));
        else return v;
      }
    }
    function primary() {
      var t = peek();
      if (t === undefined) throw new SyntaxError('表达式意外结束');
      if (/^\d/.test(t)) { p++; return parseFloat(t); }
      if (t.charAt(0) === '"') { p++; return JSON.parse(t); }
      if (t.charAt(0) === '$') { p++; return getVar(t.slice(1, -1)); }
      if (eat('(')) { var v = conditional(); expect(')'); return v; }
      throw new SyntaxError('无法解析：“' + t + '”');
    }

    var value = conditional();
    if (p !== toks.length) {
      throw new SyntaxError('表达式未完全解析：“' + toks.slice(p).join(' ') + '”');
    }
    return value;
  }

  /* ---------- 3. 语句切分与执行 ---------- */
  function splitCalls(inner) {
    var calls = [], i = 0;
    while (i < inner.length) {
      if (inner.charAt(i) !== '{') { i++; continue; }
      var depth = 1, j = i + 1, inStr = false;
      while (j < inner.length && depth > 0) {
        var c = inner.charAt(j);
        if (inStr) {
          if (c === '\\') j++;
          else if (c === '"') inStr = false;
        } else if (c === '"') inStr = true;
        else if (c === '{') depth++;
        else if (c === '}') depth--;
        j++;
      }
      calls.push(inner.slice(i + 1, j - 1));
      i = j;
    }
    return calls;
  }

  var rplcStartMark = null, rplcEndMark = null;

  function insertMark(anchor) {
    var m = document.createComment('mb');
    anchor.after(m);
    return m;
  }

  function execOne(name, arg, anchor, scope) {
    var val = function () {
      return arg === undefined ? '' : evaluate(arg, scope);
    };
    switch (name) {
      case 'v': case 'l':
        break;                                     // 元信息，无输出
      case 'put':
        anchor.insertAdjacentText('afterend', String(val()));
        break;
      case 'rplcStart':
        rplcStartMark = insertMark(anchor);
        break;
      case 'rplcEnd':
        rplcEndMark = insertMark(anchor);
        break;
      case 'rplc':
        if (rplcStartMark && rplcEndMark) {
          var range = document.createRange();
          range.setStartAfter(rplcStartMark);
          range.setEndBefore(rplcEndMark);
          range.deleteContents();
          range.insertNode(document.createTextNode(String(val())));
          rplcStartMark.remove();
          rplcEndMark.remove();
          rplcStartMark = rplcEndMark = null;
        } else {
          console.warn('[mb] rplc 找不到配对的 rplcStart / rplcEnd');
        }
        break;
      default:
        console.warn('[mb] 未知函数：' + name);
    }
  }

  function runScript(script, anchor, scope) {
    // script 形如 {{fn:arg}{fn:arg}}，先剥掉最外层的 { 和 }
    var inner = script.slice(1, -1);
    splitCalls(inner).forEach(function (call) {
      var k = call.indexOf(':');
      var name = (k < 0 ? call : call.slice(0, k)).trim();
      var arg = k < 0 ? undefined : call.slice(k + 1);
      try {
        execOne(name, arg, anchor, scope);
      } catch (e) {
        console.warn('[mb] ' + name + ' 执行失败：' + e.message);
      }
    });
  }

  /* ---------- 4. 触发器 ---------- */
  function scopeOf(el) {
    var scope = Object.create(null);
    if (el.matches('input, textarea, select')) {
      scope.cntnt = el.value;
    } else {
      scope.cntnt = el.textContent;
    }
    return scope;
  }

  function fire(el) {
    if (!el.dataset.mb) return;
    tick();                    // 时间类变量在调用时自动刷新
    runScript(el.dataset.mb, el, scopeOf(el));
  }

  function init(root) {
    root = root || document;

    // 单独成行的执行语句：加载后自动执行
    root.querySelectorAll('.mb-exec[data-mb]').forEach(fire);

    // 按钮 / 按钮式连接
    root.querySelectorAll('button[data-mb], a.mb-btn[data-mb]').forEach(function (el) {
      el.addEventListener('click', function (e) { e.preventDefault(); fire(el); });
    });

    // 输入控件：change（失焦 / 回车提交）时执行自己的执行语句
    root.querySelectorAll('input[data-mb], textarea[data-mb], select[data-mb]')
      .forEach(function (el) {
        el.addEventListener('change', function () { fire(el); });
      });

    // 回车键对应的按钮：->(#id)
    root.querySelectorAll('[data-mb-enter]').forEach(function (el) {
      el.addEventListener('keydown', function (e) {
        if (e.key !== 'Enter') return;
        var btn = document.querySelector(el.dataset.mbEnter);
        if (btn) btn.click();
      });
    });
  }

  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', function () { init(); });
  } else {
    init();
  }

  window.mb = { init: init, evaluate: evaluate, run: runScript, vars: GLOBAL };
})();

附录 B：解析规则与优先级

  1. 转义优先：\ 与紧跟其后的一个字符总是最先被识别；\o 是它的两字符写法，同样只转义紧跟其后的一个字符。被转义的内容不再参与任何后续解析。
  2. 就近配对：所有成对定界符按“向左找最近的未配对开始符”匹配。因此 【a|【b|c】】 的内层先闭合。
  3. 内层先解析：嵌套结构中，内层的内容先完成解析，结果再作为外层的内容。唯一的例外是上标 / 下标——它们内部不再解析上标 / 下标（见 3.4），但其它行内语法照常解析。
  4. 块级先于行内：折叠块、代码块、表格、原始文本等块级构造先切分，再对每一块做行内解析。
  5. mb 优先于 md：当同一位置既能匹配 md 又能匹配 mb 时，取 mb。例如 _[a]_ 是下标、_(a)_ 是注解（都不是斜体），_a_ 是下划线（斜体一律用 *a*）；~[a][b] 是折叠块而不是 md 的删除线。
  6. 长定界符优先：->[...]<- 优先于 -[...]-，[-[...]-] 优先于 -[...]-，[|[…]|] 和 [[…]] 优先于 [，+: -: %: >: 优先于 + - % >，.- .+ .? 优先于单独的 .。
  7. 不可跨空行：所有行内语法（ruby、变大、上色、转义符……）不得跨越空行，跨空行时按未闭合处理，原样输出。例外：竖排文本（[|[ ]|] / 「「」」）、原始文本（[o[ ]o]）与行间公式（$$$ … $$$）可以跨行、也可以跨空行——它们的收尾靠的是明确的结束标识，而不是“这一行完了”（见 3.16、3.19、3.23）。
  8. 未闭合即原样输出：任何未配对的定界符都按普通文本输出，不得吞掉后续内容。
  9. 输出必须转义：所有来自文档内容的文本在写入 HTML 时都要转义 & < >；只有实现明确支持的属性（如 data-mb）才做属性值转义。
  10. 空白：定界符与内容之间的首尾各一个空格不参与内容（【 汉字 | han 】 等价于 【汉字|han】）；内容中间的空格全部保留。
  11. 大小写：语法关键字（greek、put、rplcStart…）区分大小写；HTML 标签名与属性名不区分。
  12. 向前兼容：遇到不认识的 mb 语法，实现必须原样输出，不得报错丢弃。
